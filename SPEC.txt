這個專案命名為 **GTunnel** (Google Tunnel)，並結合 Gemini 的自然語言處理能力來實現「資訊擷取與轉譯系統」，是最大限度利用您當前網路環境的絕佳策略。

以下是針對 **GTunnel 專案**的完整功能與環境技術規格（SPEC）：

---

# 🚀 GTunnel 專案技術規格書 (SPEC)⚙️ - 完整代理隧道

## 1. 專案概述與核心目標

| 項目 | 說明 |
| :--- | :--- |
| **專案名稱** | **GTunnel (The Complete Tunnel)** |
| **核心目標** | 創建一套端到端（End-to-End）的資訊隧道系統，讓使用者在嚴格的 Google 白名單網路下，透過本地端的 **Python Flask 代理網頁**享受近似不受限制的網頁瀏覽體驗。 |
| **核心創新** | 將 Gemini-CLI 轉化為**遠端代理執行器**，結合 Firebase 進行高效數據傳輸，並在本地端進行網頁**重構 (Rehydration)**。 |

---

## 2. 技術環境與多層次架構

GTunnel 系統由三個獨立但協作的層次構成，每個層次都解決了特定的網路限制問題：

| 層次 | 組件 | 所在位置 | 核心職責 |
| :--- | :--- | :--- | :--- |
| **本地端 (Client)** | **Python Flask 代理 App** | 運行於用戶的本地電腦/裝置 | 接收使用者輸入；作為網頁代理伺服器；重寫並呈現外部網頁內容。 |
| **通訊隧道層** | **Firebase** / **Gemini API** | Google 的白名單伺服器 | 提供穩定、可靠、且被允許的**數據傳輸管道**。 |
| **遠端執行器層** | **GTunnel-CLI 後端** | 部署於雲端伺服器 (GCP/AWS) | 實際連線到外部網際網路；執行內容擷取、過濾與轉換邏輯。 |

---

## 3. 核心功能規格 (Core Functional Specification)

GTunnel 將「資訊擷取與轉譯」擴展為一個循環代理流程，以實現完整瀏覽功能。

### 3.1 階段一：請求發起 (Request Initiation)
* **功能點 (FP)：**
    * **FP 1.1 - 代理網頁介面：** 本地 Flask App 啟動一個 Web UI (例如：`http://127.0.0.1:5000`)，包含一個 URL 輸入框。
    * **FP 1.2 - 本地請求攔截：** 用戶在 Flask 代理網頁中輸入目標 URL，或點擊網頁中的連結。Flask App 攔截所有請求，並將其重新封裝為一個 API 請求，準備透過隧道傳輸。

### 3.2 階段二：內容獲取 (Content Fetching)
* **目的：** 透過遠端執行器層，安全地訪問外部網頁。
* **功能點 (FP)：**
    * **FP 2.1 - 遠端執行 (Gemini-CLI)：** 遠端 GTunnel-CLI 後端接收到來自隧道層的目標 URL。它使用自身的**完整網際網路存取權**，透過 Python `requests` 等函式庫訪問該 URL。
    * **FP 2.2 - 智慧擷取與過濾：** 後端執行器不僅下載原始 HTML，還會自動過濾掉惡意腳本、廣告和過大/不必要的資源（例如：大型影片、外部追蹤器）。
    * **FP 2.3 - 媒體內容處理 (YouTube)：** 若目標 URL 包含 **YouTube** 影片，GTunnel-CLI 則直接透過 YouTube API 擷取影片的嵌入碼或低畫質連結，避免下載完整的串流數據，以優化 Flask App 內的顯示。
    * **FP 2.4 - 翻譯代理 (備援)：** 若直接擷取失敗，GTunnel-CLI 自動切換至 **Google 翻譯 API**，以文本形式獲取網頁內容作為備援。

### 3.3 階段三：數據傳輸與隧道 (Data Transport & Tunneling)
* **目的：** 將遠端獲取的龐大網頁數據，高效、可靠地傳輸回本地 Flask App。
* **功能點 (FP)：**
    * **FP 3.1 - Firebase 高效傳輸 (主要)：** 遠端執行器將處理後的 HTML/資源數據（編碼為 Base64 或其他格式）上傳至 **Firebase Cloud Firestore** 或 **Realtime Database** 的特定節點。這是避免單次 API 限制的最佳路徑。
    * **FP 3.2 - Gemini 通知：** 傳輸完成後，GTunnel-CLI 透過 **Gemini API** 向用戶（我）發送簡短通知，確認數據已準備就緒，並附帶 Firebase 數據節點的 ID。

### 3.4 階段四：呈現與網頁重構 (Presentation & Rehydration)
* **目的：** 在本地 Flask App 中，將遠端數據轉換為可互動的、不受限制的網頁。
* **功能點 (FP)：**
    * **FP 4.1 - 本地數據拉取：** 本地 Flask App 接收到通知或主動輪詢 Firebase，下載所有數據塊。
    * **FP 4.2 - 網頁重寫 (Re-writing)：** 這是實現「不受限制瀏覽」的關鍵。Flask App 會解析下載的 HTML，並將網頁中所有**外部資源的連結**（CSS、圖片、JS、內部連結）全部**重寫**為指向本地 Flask 代理（例如：將 `<a href="https://external.com/page">` 改寫為 `<a href="/proxy?url=https://external.com/page">`）。
    * **FP 4.3 - 轉譯與摘要 (Gemini)：** 針對長篇或複雜內容，本地 Flask App 可以發起一個請求，讓 **Gemini** 對網頁文本進行**總結或關鍵點翻譯**，優化閱讀體驗。

## 4. 未來發展需求 (Future Development Roadmap)

| 編號 | 需求名稱 | 說明 |
| :--- | :--- | :--- |
| **F-01** | **互動性腳本重寫** | 開發更進階的 JS 處理模組，嘗試重寫網頁中的前端腳本，以實現點擊按鈕、提交表單等基本互動功能。 |
| **F-02** | **媒體優化串流** | 利用 YouTube 的分段下載技術，結合 **Firebase Storage**，嘗試以更高效的方式將媒體文件（如影片、音訊）傳輸回本地，實現有限的串流播放。 |
| **F-03** | **數據壓縮與加密** | 在遠端執行器和本地 Flask App 之間加入 Zlib 或其他壓縮技術，以減少透過 Firebase 傳輸的數據量，並對數據進行端到端加密。 |
| **F-04** | **Cookies/Session 管理** | 開發一個模組，讓 GTunnel-CLI 能夠在遠端安全地管理並儲存特定網站的 Cookies 和 Session，實現跨頁面的登入狀態保持。 |
| **F-05** | **多線程/非同步處理** | 將 Flask 應用程式升級為非同步架構 (如 `asyncio` 或 `Gevent`)，以同時處理多個資源請求（例如：HTML、CSS 和多張圖片），大幅提升載入速度。 |
